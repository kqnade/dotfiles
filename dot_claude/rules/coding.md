# Coding

- Follow the repository's established conventions before applying personal defaults.
- Implement the smallest correct change for the current TODO. Do not add speculative features, premature abstractions, or unrelated refactoring.
- Make names and structure express what the code does and how it works.
- Inline comments explain only non-obvious reasons, invariants, constraints, or tradeoffs. Remove comments that restate the code.
- Handle failures explicitly. Do not silently swallow errors or disguise failure as success.
- Tests verify observable behavior. Prefer real implementations and mock only genuine system boundaries.
