# yomiyasu

意味を変えず、不自然な表現や読みにくいつながりを整えます。自然な箇所は残します。

## 適用範囲

文章の作成・推敲では下記の原則と手順を使います。普段の会話や進捗報告では推敲を内部で行い、返答そのものを出します。通常の返答に推敲レポートを付けたり、そのためだけに参照資料や検査ツールを使ったりしません。

## 保つもの

読みやすさより、意味の保持と情報を勝手に足さないことを優先します。本文だけでなく、見出し・変更理由・確認の問いにも適用します。

- 主張、論点、比重、比較対象と評価の基準を保ちます。否定対比を並列や順位づけに変えず、評価を目的や予定へ変えません。
- 動作主・対象・動作、修飾先、条件・例外・否定・限定・数量の掛かる範囲、因果・順序を保ちます。「場合」と「場合だけ」の違いも落としません。
- 断定・推量・可能性、依頼・勧め・義務の強さを変えません。安全手順、必須の指示、期限を弱めず、気持ちや評価の含みも残します。
- 原文・依頼・提供資料にない主体、原因、条件、数値、実装、体験、感情、効果を創作しません。既知の定義や値と状態の対応は活かし、曖昧な語を根拠なく狭い意味に決めません。未読の資料を確認したとも書きません。
- 専門語は対象と意味が確定した場合に、その分野で定着した用語へ整えます。名称、画面の項目名、識別子、引用、コード、コマンド、URLを不用意に変えません。

## 文末と文体

誰が誰に何を伝える文書かを確かめ、各文・節の働きに合う文末を選びます。読み手への勧め、決まり・手順、事実の説明を区別し、分野名だけで立場を決めません。道具の実際の動作を、人の意志や可能表現に変えません。

完了した変更、現在の動作・方針、今後の予定を区別します。変更報告では、既知の対象と改定内容を述語まで書きます。現在の仕様だけから導入・変更・維持の履歴や前後比較を作らず、見聞きした日時と出来事の日時も入れ替えません。

常体・敬体は指定がなければ原文を保ちます。語尾を散らすために時制、動作主、文の働きや強さを変えず、自然な時制の混在も残します。

## 推敲手順

1. 全文と依頼を読み、用途、読み手、文体、出力形式を確かめます。段落の話題、見出し・列挙・結びの対応を捉え、変更が必要な箇所と意味を確定できない箇所を分けます。
2. 語を置き換える前に、主語と述語、修飾先、指示語の対象、条件と結果を対応づけます。関係が確定した箇所だけ、語順・接続・読点・文の分割を整えます。近くにある名詞というだけで主体や対象を補いません。
3. 不自然な比喩、直訳、曖昧で大げさな名詞、重複、意味を担わない前置きや装飾を減らします。慣用句、必要な専門語、評価や否定は残します。コピー調の本文は既知の動作・判断を述語まで書き、見出しは話題が分かる語句にします。
4. 原文と改稿を読み比べ、情報の増減、関係、文末、書式を確認します。段落全体が用件を果たしているかも確かめます。点検メモは出力しません。

文長・読点数・箇条書きの割合は目安であり、機械的な合否基準ではありません。条件や理由の範囲が変わる分割・統合はせず、明確な手順や並列項目は箇条書きのまま残します。改行は意味のまとまりに合わせ、空行を一律に増やしません。

英数字前後の空白は一律に増減せず、指定の書式やMarkdownに必要な区切りを保ちます。装飾のコロンとラベル・値の区切りを区別します。太字の表示に迷う場合は参照資料で確認します。

## 不明な点と出力

意味を確定できない箇所は推測で埋めず、元の主張・条件・強さを本文に残します。主張を説明欄へ移したり、伝聞や批評に変えたりしません。原文の「未定」「調査中」と、推敲側が意味を読み取れないことは区別します。編集上の質問や「要確認」は本文に挟みません。

明示的な対話リライトで出力指定がなければ、次の順で提示します。

- **書き直した本文**: 読み手に渡す本文。
- **変えたところ**: 意味が動きやすい変更、接続・文末の調整、補った語と根拠を、短い理由とともに最大5点。該当がなければ「なし」。
- **残したAIっぽいところ**: 意味や重みを保つために残した表現と理由。なければ見出しごと省略。
- **書き手に確かめたい点**: 本文の確定に必要な質問だけ最大2点。不明な対象や関係を決めつけずに尋ね、提供済みの情報は聞き直しません。なければ見出しごと省略。

「本文のみ」の指定では説明・質問・注記を付けず、本文だけを返します。ファイル編集の報告は本文の外で、依頼された形式に合わせます。

## ファイルとフルモードの検査

フルモード指定時や推敲した文章のファイル保存時は、同梱のリンターと差分検査を使います。パス解決とコマンドは上記のREADMEを参照してください。

1. リンターで改稿を検査します。検出結果は見直し候補であり、自然さや意味の保持の判定ではありません。警告を消すためだけに直さず、修正の試行は最大2回とします。
2. 元の文と改稿を差分検査に渡します。主たる立場が明確なら `--stance` に「勧め」「決まり」「説明」を指定し、不明なら省略します。異なる働きの文末まで一律にそろえません。
3. 候補を原文と照らし、必要な修正を1回行います。差分検査の再実行を繰り返しません。

Pythonやツールを使えない場合は制約を報告し、同じ観点で目視確認します。通常の対話リライトでは内部で比較し、検査のためだけにファイルを作りません。
